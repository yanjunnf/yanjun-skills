## 工作流程

### 步骤1：提取并校验链接
检查用户输入的prompt，提取所有要下载的视频链接，并检查链接是否有效，是否是X网站的视频链接（合法格式为 `https://x.com/{用户名}/status/{数字ID}`）。
- 链接末尾常带追踪参数（如 `?s=46&t=...`），输入下载网站前应去掉，只保留 `https://x.com/{用户名}/status/{ID}` 部分。

### 步骤2：通过网页工具批量下载
下载视频的网址是 `https://x-downloader.com/auto`，在该网页中一个接一个地输入视频链接，点击 Download Video 按钮，等待解析完成后点击 Download MP4 保存到本地，下载完成后页面会出现"下一个(Next)"按钮，点击后再输入下一个视频链接，直到下载完所有视频。

批量下载的执行要点（实测经验）：
- **分批执行**：使用 browser_use 子代理操作浏览器。批量任务不要一次交给一个代理处理全部链接（步骤多易发散、超预算），按**每批最多 3 个链接**分批串行执行（浏览器是共享的，两批不可并行）。
- **标准操作序列**（每个链接重复）：snapshot 获取输入框/按钮 ref → 填入链接 → 点击 Download Video → 用 browser_wait_for 耐心等待解析完成（出现 Download MP4 或 Next 按钮，如页面有广告倒计时需等倒计时结束）→ 点击 Download MP4 → 等待文件保存 → 点击 Next 进入下一条。
- **等待纪律**：下载进行中不要做任何其他导航/点击操作，否则下载请求会被中断（`net::ERR_ABORTED`）。
- **异常处理**：遇到广告弹窗先尝试关闭；遇到 CAPTCHA 无法自动完成时，调用 `browser_waiting_for_user_interaction`（独立调用，不放进 Exec）交由用户处理。
- **文件保存位置与路径确认**：文件直接保存到浏览器默认下载目录（通常为 `~/Downloads`），**不要逐条询问用户保存路径，直接使用默认路径**。若点击 Download MP4 后弹出"选择保存位置"确认框，说明浏览器开启了"每次下载前询问保存位置"：当场调用 `browser_waiting_for_user_interaction` 请用户完成本次确认，并在最终汇总时提醒用户关闭该选项（Chrome：设置 → 下载内容 → 关闭"下载前询问每个文件的保存位置"；Trae 内置浏览器在 IDE 的下载设置中关闭），关闭后批量下载不再逐条弹窗确认。

### 步骤3：核对落盘文件（重要，不能只信页面报告）
全部下载完成后，**必须核对本地下载目录中的实际文件**，页面报告"下载成功"不代表文件已保存。执行 `ls -lt ~/Downloads/*.mp4` 检查：

- 逐一核对每个链接是否有对应文件。注意：**页面显示的标题/文件名与实际保存的文件名可能不一致**（例如页面显示 `lyra_-_such_a_magical_moment`，实际保存为 `The_Nature_-_GKq4us.mp4`），需结合文件名语义、时间戳、文件大小、视频时长（`ffprobe`）综合判断对应关系。
- 中文文件名在终端中可能显示为下划线，属正常现象；可通过文件名末尾的短码后缀（如 `_Us5TFM.mp4`）与页面显示的文件名匹配。
- 视频元数据（title/artist）常为空，不要依赖元数据判断。

### 步骤4：失败补救
若某条链接页面显示成功但文件未落盘，或下载请求被中止（浏览器网络请求显示 `net::ERR_ABORTED`）：

1. 先重试：在页面停留在下载结果状态时再次点击 Download MP4，点击后只等待（browser_wait_for 15 秒），不做其他任何操作。
2. 若仍失败，改用直链下载：用 `browser_network_requests` 查看网络请求，找到视频文件直链（通常是 `https://api.x-downloader.com/v/{短码}/{URL编码的文件名}.mp4`），然后用 curl 下载到 `~/Downloads`：
   ```bash
   curl -L --fail -o "/Users/yanjun/Downloads/{文件名}.mp4" "{视频直链URL}"
   ```
   注意：写入 `~/Downloads` 超出沙箱可写目录范围，执行 curl 时需设置 `dangerouslyDisableSandbox: true`。
3. 下载完成后用 `ffprobe` 验证文件时长正常、可播放。

### 步骤5：汇总结果
全部处理完成后，向用户输出汇总表：
- **文件保存路径**：明确告知用户所有文件所在的目录（默认 `~/Downloads`），路径用可点击链接展示
- 下载总数、成功数、失败数
- 每条链接的对应文件名（含验证过的视频时长）
- 失败的链接单独列出，并说明失败原因与已尝试的补救措施，方便用户后续处理
- 若本次下载过程中出现过"选择保存位置"确认框，提醒用户关闭浏览器的"每次下载前询问保存位置"选项，后续批量下载即可全程免确认
